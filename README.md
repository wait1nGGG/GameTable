# GameTable：单机斗地主 + 中国象棋

两个游戏，**纯静态、零依赖、零构建** —— 直接用浏览器打开 `index.html` 即玩。
左下角「斗地主 / 中国象棋」切换玩法，两边各自的棋局都会保留。

```
index.html    页面结构 + 全部样式（内联）
doudizhu.js   斗地主：牌型判定、AI、渲染、事件（单个 IIFE）
xiangqi.js    中国象棋：规则引擎、AI、渲染、交互（单个 IIFE）
tools/        无头自测 / 自对弈（node 直接跑，不参与页面运行）
```

---

## 玩法切换

左下角底栏最上面一排是**玩法切换**：斗地主 / 中国象棋。切走时另一个玩法会被「冻结」
（停掉定时器，局面留在内存里），切回来接着下；切换玩法不会丢棋局。

「简单 / 普通 / 困难」**两个玩法共用**，换难度会重开当前玩法的一局。

---
## 斗地主

- 3 人局：你 + 电脑A + 电脑B。抢地主 → 定地主 → 出牌。
- 抢地主人数为 2 时用**石头剪刀布**定地主，为 3 时先**手心手背**淘汰一人再猜拳。
- 点牌选中（也可按住拖动多选），「提示」给一手推荐，「不出」在非领出时可点。
- 右下角 **OP** 面板是作弊开局，玩家必当地主先手：可固定刷出炸弹 / 飞机 / 王炸，
  也可以来一手 **烂牌**（算法生成的散牌，体验逆风局）或 **好牌**（5 连飞机带 5 单，20 张一把走完）。
  烂牌**无王、无 2、无 A、不成炸**，实测当地主的胜率只有 2.5%（同样条件下随机 20 张是 55%）——
  怎么调出来见下面「烂牌是怎么挑的」。
- 右下角 **记牌器** 显示的是「外面还剩几张」= 总数 − 已出 − 我的手牌；剩 4 张时标红提示可能有炸弹。
  （两个浮层都比按钮宽，同时展开会互相遮挡，所以展开一个会自动收起另一个。）
- 左下角可切换 **简单 / 普通 / 困难**，切换后立即重开一局。

## 牌型

单张、对子、三张、三带一、三带二、顺子（≥5 张，不含 2 和王）、连对（≥3 对）、
飞机（≥2 个连续三张）及其带单/带对、四带二单、四带两对、炸弹、王炸。

## AI 设计

目标是「像中等水平玩家」，所以走**静态规则 + 有限搜索**的路线，不做深度搜索。
三个环节：**拆牌 → 牌组评分 → 策略栈**。

**拆牌**（`splitHand`）按固定优先级把一手牌拆成「一次能出掉」的牌组：
王炸 → 炸弹 → 飞机 → 顺子/连对 → 三张 → 对子 → 单张，最后给三张/飞机配最小的带牌。
顺子与连对存在先后顺序之争（`3344556789` 该拆连对还是顺子），因此两种顺序各算一遍取高分。

**评分**（`scoreGroups`）给每个牌组打分（越能管牌、越难被管，分越高），
再减去轮次惩罚：`Σ牌组分 − P(组数) × 组数`，P 随组数递减。
王/2/炸弹那一轮总能出去，不计入轮次。

**记牌与赢牌路径**：用「总数 − 已出 − 我的手牌」推出外面的余牌，
判断每个牌组是否还可能被管住。若会被管的牌组 ≤1 个，就先把不会被管的出完、
把唯一会被管的那组留到最后 —— 因为出完最后一手即获胜，这是一条**必胜路线**。
残局里 AI 靠这条规则收官，是它最难对付的部分。

**接牌**会区分：是不是队友的牌、对手还剩几张、动这手牌会不会拆散自己的顺子/对子/炸弹。
对手 ≤2 张时不计代价拦截（优先不用炸弹）。

**队友的牌不是一律不压**。上家是队友时按这个顺序判断：
队友 ≤2 张 → 让队友走；地主 ≤2 张 → 必须接管；否则看「这一手能不能直接收掉，
或出完能进入必胜路线」——能才接管，不能就让过（`cooperate` 开关，困难档才开）。

**炸弹只在炸得有价值时才炸**（`bombCost`）：能一把走完、或炸完能进入必胜路线，
就算 0 代价；否则按 `leadBomb` / `followBomb` 扣分。这样既不会为了「赢这一手」
白白交炸，关键回合也不会因为怕扣分而不敢炸。

**角色不同打法不同**（`bigScale`）：地主一打二，大牌舍得用、抢牌权优先；
农民二打一，大牌留着拦地主收官。**收尾警戒**（`endgame`）则在对手剩牌进入
警戒线后抬高抢牌权权重（`followUrgent` / `passEndgame`），别把牌权轻易交出去。

留了软采样（top5 候选按分数加权抽签），所以 AI 不会每局都走同一条线。

### AI 强度

三档不只是数值差，**能力也不同**（见 `DIFFICULTY` 里的开关）：

| 开关 | 简单 | 普通 | 困难 |
|---|---|---|---|
| 记牌 `useMemory` | ✗ | ✓ | ✓ |
| 必胜路线 `useWinPath` | ✗ | ✓ | ✓ |
| 农民配合 `cooperate` | ✗ | ✗ | ✓ |

自对弈实测（`tools/selftest.js`，A 方一半当地主一半当农民，每格 5000–6000 局）：

| 难度 | vs 上一版（`d42da8e`）同档 |
|---|---|
| 简单 | 48.2% |
| 普通 | 62.7% |
| 困难 | 60.4% |

| 对阵 | A 方胜率 |
|---|---|
| 简单 vs 普通 | 21.3% |
| 普通 vs 困难 | 42.3% |
| 简单 vs 困难 | 17.5% |

普通 / 困难都比上一版明显更强；简单档因为关掉记牌与必胜线，比上一版略弱 —— 这是刻意的，
三档要能一眼看出差别。所有参数集中在 `doudizhu.js` 的 `AI` 与 `DIFFICULTY` 两个对象里，
想调风格改这一处即可。

### 烂牌是怎么挑的

`generateBadHand()` 只做两件事：**限死牌池** + **挑最烂的一手**。

牌池只取 **3~K**：无王、无 2、**无 A**，且单点最多 3 张（不成炸弹）。
去掉 A 是实测出来的最关键一步 —— 手里留着 A，地主还能靠它赢一手、抢到牌权；
一张 A 都没有就全程被动。同样 250 手 × 6 局的实测：

| 牌池 | 地主胜率 |
|---|---|
| 3~A（给 A） | 9.3% |
| 3~K（不给 A） | **2.7%** |
| 3~Q（连 K 也不给） | 2.8% |
| 完全随机 20 张（参照） | 55% |

坏度 = `手数 × 10 − 牌点总和 × 0.07`（手数越多越烂，同等手数下牌点越小越烂），
按低点偏置随机采样 6000 手取最烂的一手。

**试过但没用的写法**（别再重复踩）：按可成链长度重罚顺子/连对/飞机、
最小化 AI 自己的 `handStrength`、随机起步 + 爬山换牌。实测它们的地主胜率都在同一档
（8~9%）甚至更差。尤其「禁止成链」那条反而更强：要从 3~A 里凑够 10 个点数又不出现
5 连顺子，就必须往 J/Q/K 上走，牌点被顶高，地主反而更能赢。

改完务必用 `node tools/selftest.js op` 复测（它会实测地主胜率并与随机牌对照），别凭感觉。

## 实现注意：异步与打断

一局的所有延迟动作（AI 出牌、发牌、猜拳、结算…）都必须走 `Game._schedule()`，
**不要直接写 `setTimeout`**。原因：

「重新开始」和「切换难度」是丢掉旧的 `Game` 实例、新建一个。但旧实例已经排进
`setTimeout` 的回调不会随之消失，它们跑起来会调用 `renderAll(this)`，把**上一局的画面
重新画回屏幕**，接着又通过 `_executePlay → _schedule(() => this._aiTurn())` 继续把旧局打下去，
看起来就是「画面跳回上一把，再跳回新一局」。

`_schedule` 是唯一的调度入口，因此打断只需要在这一处做：回调执行前检查 `this._alive`，
`resetGame()` 调 `destroy()` 把 `_alive` 置 false 并清空定时器队列。

## 中国象棋

### 两种对局

- **普通对局**：标准开局，你执红或执黑（在「设置」里切，切了立刻重开），红先走。
- **自定义对局**：摆任意局面，也就是**残局编辑器**。棋子托盘选中一枚 → 点棋盘落子；
  直接点棋盘上已有的棋子可以移除。配「清空棋盘 / 标准开局 / 载入示例残局」。
  摆完在设置里选「我执红/黑」和「先走红/黑」，点**开始对局**进入对弈。
  摆子过程**全程可撤回**。

  自定义局按下「开始对局」前会校验局面是否合法：双方各一个将/帅、士象将不出九宫、
  象不过河、兵卒位置合理、兵种数量不超上限、**将帅不照面**、且「没轮到走的一方不能正被将军」。
  不合法的原因会直接写在顶部状态条上。

- 棋盘**会跟着你执哪方翻转**（执黑时黑方在下），和自己的棋感一致。

### 交互

- **点选是主路径**：点自己的棋子 → 高亮所有合法落点（空点是小圆点、可吃子是红圈）→ 点目标落子。
  鼠标端另外支持拖拽。之所以不做成只能拖拽，是因为 WCAG 2.2 要求拖拽不能是唯一操作方式。
- 上一步的起点终点有虚线标记；被将军时，被将的将/帅上加红圈脉冲。
- **撤回**：点一次退回自己上一次决策之前（等于同时撤掉电脑那一步和自己那一步），
  可以一直退到开局；吃子动画、走子滑动都是保留元素做 CSS 过渡，不重建 DOM。
- **输了也能悔棋**：结算浮层上除了「再来一局」还有「撤回一步」——
  浮层会盖住底栏，所以撤回入口在结算面板里必须另放一个。

### 规则

完整走法 + 蹩马腿 / 塞象眼 / 象不过河 / 过河兵 / 九宫限制 / 将帅照面，
将军、**将死与困毙都判走子方负**（象棋里困毙不是和棋），三次重复局面判和。
**没有做**长将 / 长捉判负 —— 判法与平台相关、太容易吵架，休闲向不值得。

走法生成的正确性用 **perft** 卡死：初始局面 depth 1~4 必须等于 `44 / 1920 / 79666 / 3290240`，
对不上就说明蹩马腿 / 塞象眼 / 飞将写错了，先修规则再谈 AI。

### 象棋 AI

`negamax + alpha-beta + 迭代加深`，评估 = 子力 + 位置表（7 种棋子各有 PST）+ 士象完整度。
着法排序用 置换表着法 → MVV-LVA → 杀手着法 → 历史表，并有静止搜索（只搜吃子）。

三档难度（`XQ_LEVELS`）：

| 难度 | 单步预算 | 最大深度 | 随机窗口 | 静止搜索 | 置换表 | 杀手/历史 |
|---|---|---|---|---|---|---|
| 简单 | 80ms | 1 | ±190 分 | 限 1 层 | ✗ | ✗ |
| 普通 | 350ms | 6 | ±30 分 | 限 4 层 | ✓ | ✓ |
| 困难 | 700ms | 10 | 0 | 限 8 层 | ✓ | ✓ |

简单档只搜 1 层、再叠一个很大的随机窗口：它「不会明显白送子」（静止搜索会看到
对手一步吃子），但看不出两步以上的东西、也不组织进攻。

**关于卡界面**：`file://` 下浏览器基本不允许加载 Web Worker（文档 origin 是 `null`），
所以没走 Worker。迭代加深写成生成器，**每搜完一层就让出主线程**；每层只给「上一层耗时 ×3」
的预算，并且事先估算「这层大概率搜不完就不开始」—— 这样单次阻塞被压在很小一段，
既不会出现 1 秒级的卡死，也不会因为时间不够而搜出半层垃圾结果。

## 界面

配色取自「毡面绿 + 金 + 深色底」的棋牌组合，质感走轻拟物：木质外框、绒面毡桌、多层阴影、按压缩放。
颜色、圆角、动效时长都收在 `index.html` 顶部的 `:root` 里，改一处即可整体换肤。

几条自己踩过的坑，改样式时注意：

- 牌桌由 `#game-container` 铺木纹、`::before` 用 `inset:var(--rail)` 把中间"挖"成毡面。
  **不要再给 `::before/::after` 加 `inset:0` 的背景**，否则会像早期版本那样整块盖住毡面。
- 手牌区用 `padding-bottom: var(--hud-clear)` 抬到底部两组 HUD 之上，否则最左边几张会被压住。
- 图标一律用内联 SVG（`<symbol>` + `<use>`），不用 emoji：emoji 跨平台字形不一致，也没法跟着文字颜色走。
  猜拳的 ✊✌️✋ 和手心手背的 ✋✊ 是游戏内容不是图标，保留。
- 底栏现在有两排（上排玩法切换、下排难度/操作），`--hud-clear` 要按两排的高度给。
- 象棋棋盘线用 SVG：**`#xq-grid` 的 `viewBox` 必须设成 `0 0 9.6 10.6`（以「格」为单位）**。
  漏了它，所有坐标会被当成像素画在左上角 9.6×10.6 像素里，看起来就是「棋盘一条线都没有」。
- 象棋每格边长 `--cs` 由 JS 按可用空间算；算的时候要**自己减掉 `#xq-zone` 的 padding**——
  `clientHeight` 是包含 padding 的，改了 padding 它不变，棋盘就不会重排（摆子时托盘会盖住棋盘底行）。

## 自测

`doudizhu.js` 是单个 IIFE、不导出任何东西。`tools/selftest.js` 把 `RENDERER` 标记之前的
纯逻辑切出来 `new Function` 求值（不需要 jsdom），再自己写一个最小的对局循环：

```
node tools/selftest.js rules                  # 斗地主：牌型判定 / canBeat / generateCombos / 拆牌不变式
node tools/selftest.js op                     # 斗地主：OP 开局生成（好牌一手可走完、烂牌无王无2无A无炸）
                                              #   └ 会顺便实测烂牌的地主胜率，和「随机 20 张」对照
node tools/selftest.js game                   # 斗地主：给渲染层打桩，跑 5 个 OP 开局 + 普通发牌
node tools/selftest.js duel 困难 困难 6000     # 斗地主：单挑，输出 A 方胜率与 95% 置信区间
node tools/selftest.js bench 3000             # 斗地主：三档互打 + 对阵基线的完整表
node tools/selftest.js xq 4                   # 象棋：perft（初始局面 depth 1~4 的标准值）+ 规则单测
node tools/selftest.js xqai 困难 3            # 象棋：一步杀 / 白吃子 / 自对弈合法性
```

象棋那边同样是把 `xiangqi.js` 里 `RENDERER` 标记之前的纯逻辑切出来求值，所以**那个标记不要改名**。

`tools/baseline.js` 是上一版斗地主 AI 的快照（就是提交 `d42da8e` 的 `doudizhu.js`），
只用于自对弈对照，**没进版本库**。想用 `bench` / `duel` 里「vs 基线」那几行就先还原它：

```
git show d42da8e:doudizhu.js > tools/baseline.js
```

没有这个文件时，其余命令照常运行。
